# Security and failure model

## Credential handling

- The connected-cluster access key is generated by Platform for exactly one
  `Cluster` identity.
- A short-lived VCI access-key token is requested with a configurable TTL of
  60–3600 seconds (600 by default).
- The kubeconfig request impersonates the configured Platform User or Team so
  Platform assigns ownership and VCI scope to the temporary access key. The
  controller has `impersonate` permission for users and groups; write access to
  `KubeVirtProviderCluster` is therefore an infrastructure-admin capability.
- The temporary kubeconfig exists only in process memory.
- The kubeconfig uses the vCluster Platform proxy; no direct VCI API endpoint is
  required. The only operation performed through it is namespace/Secret
  create-or-update.
- The agent token is stored only in the provider VCI Secret.
- Argo and the `ArgoCDApplication` contain only the Secret name.
- The Platform CA is not confidential and may appear in application values.

The controller logs errors returned by APIs. It does not log request bodies,
kubeconfigs, access keys, or Secret data.

## Reconciliation boundaries

The controller does not attempt to rotate a successfully staged agent key.
Platform owns the connected agent after enrollment. Deleting the bootstrap
Secret later is an operator error and requires recreation of the composite or a
future explicit rotation workflow.

The VCI template owns Private Node configuration and the Argo connector. The
controller waits for VCI readiness but does not rewrite rendered vCluster
values. It does not gate enrollment on the aggregate `ArgoCDIntegrationSynced`
condition because unrelated VCI applications also contribute to it.

## Failure behavior

- Invalid specs surface `Ready=False` without retry storms.
- Transient API failures are rate-limited and retried.
- Argo, agent, and NodeProvider readiness are polled through the 30-second
  informer resync.
- Reconciliation state transitions and managed-resource creation are logged;
  repeated unchanged waits are not logged.
- Name collisions fail closed; pre-existing objects are not adopted.
- The connected Cluster is never made schedulable (`unusable` remains true).
- Ordered deletion keeps connectivity available until the NodeProvider and
  agent application have been removed.
